1. このシステムは何をしているのか？
全体概要と目標

人間の顔をカメラで見つけ、カメラを載せた2軸モータが「1秒間に60回（60 FPS）」の滑らかさで視線を追尾し続けるシステムです。

👀 みる（コンピュータビジョン）

  • CSIカメラから高品位映像をキャプチャ
  • エッジAI（MediaPipe BlazeFace）が顔の位置・鼻先を高速特定
  • 画面中心からの「ズレ（偏差）」をリアルタイム計算

🤖 うごく（制御工学 & メカ）

  • PDフィードバック制御で適切な速度を算出
  • 左右（Pan）と上下（Tilt）のサーボモータを駆動
  • 顔を見失った時は自動で周囲を捜査（自律パトロール）
💡 工学的な見どころ： 単なるAIの動体検知だけでなく、「推論の高速化」「描画の非同期化」「モータの物理保護」が1本のコードに凝縮されています。
2. ハードウェア構成（全体アーキテクチャ）
Jetson Nanoを中心とするエコシステム

手のひらサイズのシングルボードPC NVIDIA Jetson Nano が頭脳として動作します。

🧠 Jetson Nano

Maxwell GPU（128コア）を搭載。PC用の重いディープラーニングモデルを現場（エッジ）で直接推論可能。

🎥 CSIカメラ (IMX219)

USBと違い、GPU直結のMIPI-CSIバスで接続。CPUに負荷をかけずに1280x720 60FPSの生映像をDMA転送。

⚡ PCA9685 & サーボ

I2C通信（アドレス0x40）で制御する16ch PWM基板。高精度なパルス幅（500〜2400μs）でサーボ角を滑らかに維持。

データの流れ： カメラ映像 [MIPI-CSI] ➔ Jetson GPU [推論・座標計算] ➔ PCA9685 [I2C通信] ➔ モータ駆動 [PWM]
3. なぜ普通のコードでは 60 FPS が出ないのか？
ボトルネックの正体

入門書にある単純なループを書くと、10〜15 FPS（カクカク）まで性能が落ちてしまいます。

# ❌ 初心者がやりがちな同期直列ループ（15 FPS前後で破綻）
while True:
    ret, frame = cap.read()       # ① カメラ画像取得待機 (約16ms)
    faces = detector.detect(frame)# ② CPUでのAI推論 (約50〜80ms) ⚠️激重
    servo.set_angle(...)          # ③ I2C通信でモータ更新 (約5ms)
    cv2.imshow("Track", frame)    # ④ X11ウィンドウ画面描画 (約20ms) ⚠️重い
    cv2.waitKey(1)
    # 合計: 100ms以上 ➔ 1秒間に10回しか回らない！

⚠️ ボトルネック①：CPU演算の限界

一般的な顔検出DNNは数十万回の積和演算を行うため、Jetsonの省電力ARM CPUでは処理しきれません。

⚠️ ボトルネック②：GUI描画の待ち時間

imshow や文字・矩形の描画はOSのGUIサーバと通信するため、追従モータの更新まで止めてしまいます。

4. 解決策①：MediaPipe & GPUデリゲート
8.5ms の超高速顔推論

本コードでは、Googleの超軽量顔検出モデル BlazeFace を OpenGL ES 3.2 GPUデリゲート で動作させています。

CPU推論 (通常)

  • 推論時間: 40〜70 ms
  • FPS: 15〜20 FPS 程度
  • CPU 4コアが100%になり発熱

🚀 GPUデリゲート (本スクリプト)

  • 推論時間: わずか 8.5 ms！
  • FPS: 55〜60 FPS 安定動作
  • GPUのシェーダ並列処理でCPUがほぼ空き状態
# GStreamerハードウェアパイプライン (nvvidconvでGPU内でリサイズ & 双線形補間)
csi_pipeline = (

キューの長さをあえて「1」に制限。もし画面描画が一瞬引っかかっても、古いフレームは即座に捨てて常に最新フレームのみを表示。モータ制御への遅延波及（レイテンシ爆発）をゼロにします。
6. 制御工学：ただ回すだけでは振動して止まらない！
PD制御（比例・微分フィードバック）

顔が右にズレた時に「ズレの分だけ右にモータを回す（比例＝P制御）」だけだと、慣性で行き過ぎて左右に激しく振動（ハンチング）します。

P制御（比例項）

Kp × 誤差 (err)

ズレが大きいほど強く回す「バネ」の役割。これだけだと目標を行き過ぎて揺れ続ける。

D制御（微分項）★超重要

Kd × 変化速度 (d_err / dt)

急激に目標に近づくと逆向きの力をかける「ダンパー（油圧ブレーキ）」の役割！ピタッと静止する。

# SafeServoController.update() 内の実装
err_x = target_norm_x - 0.5                      # 画面中心からの偏差 (-0.5 〜 +0.5)
d_err_x = (err_x - self.prev_err_x) / dt         # 偏差の変化速度 (微分)

# P項で引っ張り、D項でブレーキをかけてピタッと止める
step_pan = self.PAN_DIR * (err_x * self.KP_PAN + d_err_x * self.KD_PAN)
step_pan = max(-self.MAX_DELTA, min(self.MAX_DELTA, step_pan)) # 振り切れ遮断
7. ロボットを壊さないための安全設計
実機ハードウェア制御の必須知識

プログラムが暴走しても、物理モータのプラスチックギアを破損（ギア欠け）させない3重の防護策を組み込んでいます。

1. 可動域ソフトウェアリミット

サーボの物理限界（0°/180°）の手前で強制クランプ。
PAN: 20°〜160°
TILT: 35°〜145°

2. 変位角リミッター (MAX_DELTA)

1回の更新での最大変化量を 1.0° に制限。誤検出による急激な振り切れや衝撃を物理遮断。

3. 不感帯 (デッドゾーン)

画面中央 ±3.5% 以内は出力をゼロに。微小なノイズによるサーボの唸り（ジジジ音）と発熱・磨耗を防止。

🛡️ ソフトリターン（安全終了）：
Ctrl+C や 'q' キーで終了した際、finally 節でカクンと倒れるのを防ぎ、徐々に安全な初期位置（Pan 90°, Tilt 75°）へゆっくり戻してから安全に終了します。
8. 自律捜査モード（顔を見失ったら？）
状態遷移マシン & 2D空間パトロール

顔が画面から消えた際、ロボットはインテリジェントな状態遷移マシンとして振る舞います。

1. HOLD（位置保持：1秒間）

瞬きや障害物の横切りで慌てて動かないよう、直近の角度を1秒間キープ。

2. SEARCHING（自律走査）

1秒以上見失うと、首を振って周囲を探索。人が座る目線高さ（Tilt 55°〜95°）を優先してスキャン。

選べる2つの探索パターン

  • Wave スキャン（デフォルト）：
    PanとTiltを異なる周期で同時に連続波状駆動し、2D空間をくまなく探す。
  • Raster スキャン：
    左右を端まで見たら高さを段階的に切り替えるステップ式走査。

※画面右下には現在カメラがどこを探しているかを示す「2DレーダーHUD」をリアルタイム表示！

9. 実践トラブルシューティング事例
なぜ「80cm離れると顔検出できない」が起きたのか？
🚨 実際に発生した課題：「カメラから80cm離れると、目の前にいるのに顔検出が全く動かなくなる」

🔍 解析された根本原因

  1. 着座アイレベルの幾何学的ズレ：
    初期チルト90°（水平）では、80cm離れた人の顔は画面上端ギリギリに見切れていた（見切れるとAIスコアが0.24へ激減）。
  2. 縮小補間の劣化：
    ハードウェア縮小が最近傍法（Nearest）だったため、遠方の顔の目や鼻のエッジが間引かれていた。
  3. 探索方向の逆転：
    チルト探索が床（下向き）を走査していた。

✨ エンジニアリングによる解決

  1. 初期チルトを人の着座目線（Tilt = 75°）に変更。
  2. GStreamerに双線形補間（interpolation-method=1）と解像度向上（640x360）を適用。
  3. 信頼度しきい値を背景ノイズが出ない最適値（0.4〜0.6）に調整。

➔ 80cm先での検出成功率が 0% から 100%（信頼度スコア 95%）へ劇的改善！
